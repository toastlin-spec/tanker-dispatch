# 油罐車派車管理系統：規格書

版本：v1（2026-10-30）
狀態：需求已與使用者確認，第一階段開發中。

## 1. 目標與範圍

這套系統給調度員使用，用來安排油罐車的出車行程：

1. 從出發廠（台中廠、麥寮廠）出車。
2. 到灌油點（彰濱廠、R89 廠）灌油。
3. 送到各加油站卸油。

系統會自動算出每一趟的時間軸，並檢查排班規則。

- **使用者：** 只有調度員，司機不使用系統。
- **部署：** 放在雲端；第一階段不串接其他系統。
- **介面語言：** 繁體中文。
- **時區：** 一律 Asia/Taipei。

## 2. 名詞

| 名詞 | 說明 |
|---|---|
| 出發廠（depot） | 司機每天出車與收車的地方：台中廠、麥寮廠 |
| 灌油點（loading） | 灌油的地方：彰濱廠、R89 廠 |
| 油站（station） | 收油的加油站，共 10 站 |
| 訂單（order） | 油站叫油：油站、油品、數量、日期 |
| 車趟（trip） | 灌油一次，再送一站或兩站 |
| 班表（duty） | 一位司機一天的所有車趟：從出發廠出車開始，到回出發廠收車為止 |
| 路段（leg） | 兩個據點之間的油罐車行車時間（分鐘），有方向性 |

## 3. 據點

完整資料在 `data/locations.json`。

| 區域 | 灌油點 | 油站 |
|---|---|---|
| 中部 | 彰濱廠 | 苗栗站、清水梧棲站、彰化站、台中交通站 |
| 南部 | R89 廠 | 麥寮站、嘉泰站、嘉益站、六甲站、燕巢站、潮州站 |

- R89 位在麥寮廠「更裡面」，南部的車回程會先經過麥寮廠。
- 大夜班例外：大夜班從 R89 灌油，可以送中部的 24 小時油站。
- 油站營業時間：
  - 24 小時：清水梧棲站、彰化站、苗栗站、六甲站。
  - 其他：麥寮站 05–22、台中交通站 08–17、嘉益站 07–22、嘉泰站 06–22、燕巢站 06–22、潮州站 06–23。
  - 營業時間都可以在設定頁修改。

## 4. 車輛與裝載

- 每位司機有固定的車：車頭加油槽，兩者聯結但可以分開。
  - 基本上不換掛；特殊情況允許調度員手動換掛。
- 油槽 30KL，分成兩個 15KL 的艙（數值可設定）。
- 每艙只能裝一種油品：92、95 或柴油。
- **同一趟不能同時裝汽油和柴油。** 汽油趟可以一艙 92、一艙 95。
- 一艙只供應一張訂單。
  - 訂單量 15KL 以下：用一艙，可以不裝滿。
  - 訂單量 15～30KL：用兩艙。
  - 訂單量超過 30KL：拆成多趟。
- 一趟最多送兩站，也可以同一站兩艙（例如 92 和 95 各一艙）。

## 5. 訂單

- 油站叫油，由調度員建立訂單。欄位：油站、日期、油品、數量（KL，不一定是 15 的倍數）、希望到達時段（選填）、備註。
- 訂單狀態：待派 → 已排 → 已完成；或已取消。
- **每日單數上限**（可設定，超過時跳警告）：
  - 台中廠：每位司機每天最多 3 單。
  - 麥寮廠：3 位司機合計每天最多 6 單。

## 6. 車趟組成與時間計算

### 6.1 路段時間

- 路段時間在 `data/legs.json`，可在設定頁修改。
  - `bidirectional: true` 代表雙向時間相同。
  - 系統要能分別修改兩個方向。
- 新增路段的建議值：取 Google 地圖小客車時間的下限，乘以油罐車倍數（預設 1.5，可設定），再進位到 5 分。
- **缺路段時，不可自行假設時間。** 班表標示「缺少路段時間：A→B」，並提供連結到設定頁補上。

### 6.2 作業時間（可設定）

- 灌油：30 分。
- 卸油：每站 30 分；同一站兩艙仍算一次卸油。
- 出車前檢查：預設 0 分，可設定。

### 6.3 班表組成規則

1. 從司機所屬的出發廠出車。大夜班固定 00:00 出車，日班出車時間由調度員指定。
2. 每一趟的灌油點：
   - 依該趟第一站的區域決定：中部到彰濱、南部到 R89。
   - 大夜班一律到 R89。
   - 調度員可以手動改。
3. 灌油後依順序送一站或兩站，順序可以拖曳調整。
4. 每一趟送完：
   - 還有下一趟，就到下一趟的灌油點灌油。
   - 最後一趟送完，直接回出發廠，不必繞回灌油點。
5. 抵達油站時：
   - 還沒開門：自動插入「等待」直到開門，並顯示等待時間。
   - 卸油結束時間超過關門時間：標示違規。
6. 大夜班只能排在班表期間有營業的油站，主要是 24 小時站。

### 6.4 驗算範例（核心模組的單元測試必須涵蓋）

**範例 A：台中廠，苗栗站一天兩趟，06:00 出車**

| 項目 | 時間（分） |
|---|---|
| 台中廠→彰濱 | 45 |
| 灌油 | 30 |
| →苗栗站 | 90 |
| 卸油 | 30 |
| →彰濱 | 90 |
| 灌油 | 30 |
| →苗栗站 | 90 |
| 卸油 | 30 |
| →台中廠 | 60 |

合計 495 分（8 小時 15 分），14:15 收車。

**範例 B：大夜班，六甲站一趟加嘉泰站一趟，00:00 出車**

| 時間 | 動作 |
|---|---|
| 00:00 | 麥寮廠出車 |
| 00:20 | 到 R89，開始灌油 |
| 00:50 | 灌完出發 |
| 02:30 | 到六甲站，開始卸油 |
| 03:00 | 卸完，前往 R89 |
| 04:40 | 到 R89，開始灌油 |
| 05:10 | 灌完出發 |
| 06:40 | 到嘉泰站（06:00 開門），開始卸油 |
| 07:10 | 卸完，回麥寮廠 |
| 08:20 | 收車 |

**範例 C：台中交通站營業時間 08–17**

05:00 從台中廠出車：

1. 05:45 到彰濱，灌油到 06:15。
2. 07:00 抵達台中交通站，系統插入 60 分等待。
3. 08:00 開始卸油，08:30 卸完。
4. 回台中廠 20 分，08:50 收車。

## 7. 排班規則

以下規則都可在設定頁開關，也可以設定阻擋或警告。

| 規則 | 預設 | 等級 | 說明 |
|---|---|---|---|
| 做六休一 | 開 | 阻擋 | 同一司機連續有班的日曆天數最多 6 天 |
| 兩天之間休息 | 開 | 阻擋 | 前一天最後一趟回到出發廠，到隔天第一趟出車，至少間隔 11 小時。要跨日檢查，大夜班也適用 |
| 油站營業時間 | 開 | 阻擋 | 卸油不能超過關門時間（開門前會自動等待） |
| 缺少路段時間 | 開 | 阻擋 | 無法計算時間的班表不可發布 |
| 每日單數上限 | 開 | 警告 | 見第 5 節 |
| 每日駕車時數 | 關 | 警告 | 10 小時（汽車運輸業管理規則第 19-2 條） |
| 連續駕車 | 關 | 警告 | 4 小時要休息 30 分（第 19-2 條） |
| 每日工時 | 關 | 阻擋 | 12 小時（勞基法第 32 條） |
| 每月加班 | 關 | 阻擋 | 46 小時（勞基法第 32 條） |

- 使用者決定：工時與加班先不計算，所以後四項預設關閉。但系統仍要保存每趟的計畫時間，之後打開規則時資料都在。
- 規則等級為「警告」時：調度員要填寫原因才能發布，原因存入操作紀錄。

## 8. 資料模型（概要）

- **Location：** id、name、type（depot / loading / station）、region（central / south）、address、googleName、lat、lng、hours24、openTime、closeTime、defaultLoadingId。
- **Leg：** fromId、toId、minutes、source（excel / confirmed / google_x1.5 / estimate / manual）、note、updatedAt。
- **Driver：** id、name、homeDepotId、shift（day / night）、vehicleId、active。
- **Vehicle：** id、tractorPlate、trailerPlate、compartments（例如 [15, 15]）。
- **Order：** id、stationId、date、product（92 / 95 / diesel）、quantityKL、windowStart、windowEnd、status、note。
- **Duty（班表）：** id、driverId、date、startTime、status（draft / published）。
- **Trip（車趟）：** id、dutyId、seq、loadingId、drops[]。每個 drop 有 orderId、stationId、compartmentIdx[]、seq。
- **Setting：** key/value（JSON），存放作業時間、倍數、單數上限、規則開關。
- **AuditLog：** 操作紀錄，包含警告原因。

計算出的時間軸（各段的開始與結束時間）不存表，每次由核心模組即時計算。發布時另外存一份快照，作為派車單內容。

## 9. 畫面

1. **調度看板（主畫面）**
   - 選日期。
   - 左側是待派訂單，可依區域和油品篩選。
   - 右側是司機列甘特時間軸：
     - 時間範圍 00:00–24:00，大夜班也要看得到。
     - 色塊分為行駛、灌油、卸油、等待。
   - 把訂單拖到司機列：自動建立或併入車趟，自動選灌油點、分配艙位。
   - 每列顯示收車時間、單數和規則狀態（綠／黃／紅），點開可看違規原因和修正建議。
   - 按「發布」時檢查規則，然後產生派車單。
2. **訂單管理**：新增、修改、取消、依日期查詢。
3. **設定頁**
   - 油站與營業時間。
   - 路段時間矩陣：可直接編輯，並標示資料來源；缺少的路段要醒目標示。
   - 作業時間與倍數。
   - 單數上限。
   - 排班規則開關與等級。
4. **司機與車輛**：所屬廠、班別、固定車輛、車頭與油槽車牌。
5. **派車單**：每位司機一張，列出時間、地點、油品與數量；可以列印或存成圖片。

## 10. 技術架構

- **全端 TypeScript，npm workspaces monorepo：**
  - `packages/core`：純 TypeScript，沒有 I/O。內容包含時間計算、車趟組成、艙位分配和規則檢查；前端和後端共用。
  - `apps/api`：NestJS + Prisma + PostgreSQL。
  - `apps/web`：React + Vite + Ant Design（zh_TW 語系）。看板自己寫時間軸元件，拖曳用 dnd-kit。
- 初始資料從 `data/*.json` 匯入。
- **部署：** GCP Cloud Run 加 Cloud SQL，台灣區（asia-east1）。
- **測試：** 核心模組用 Vitest 寫單元測試，必須包含第 6.4 節的範例。

## 11. 第一階段完成標準

1. 一個指令就能在本機啟動 API 和前端，並自動匯入 `data/` 的初始資料。
2. 設定頁可以修改油站營業時間、路段時間、作業時間、倍數、單數上限和規則；存檔後看板立即用新值重算。
3. 可以建立、修改、取消訂單。
4. 調度看板：
   - 能把訂單拖給司機。
   - 自動組成車趟並算出時間軸。
   - 正確套用第 6.3 節的規則和第 7 節的規則。
   - 違規時顯示原因。
5. 可以發布班表並列印派車單。
6. 核心模組的單元測試全部通過，且包含第 6.4 節的範例 A、B、C。

## 12. 之後的階段

## 13. 目前的假設（之後可調整）

- 司機和車輛名稱先用佔位資料（司機 A～D、車 1～4），由使用者在設定頁改成真實資料。
- 出車前檢查時間預設 0 分。
- 中部站回 R89 的時間（大夜班第二趟用）：先用「站→麥寮廠」加 20 分估計，標為 estimate。
- 麥寮站、嘉泰站、嘉益站、六甲站、燕巢站、潮州站還沒有座標，不影響計算。
